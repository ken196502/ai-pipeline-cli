# xdev 硬编码文章与选题去重修复方案

## 1. 背景与问题定位
在早期版本中，xdev 流水线存在三个严重的假实现与硬编码问题：
1. **成稿函数硬编码**：`synthesizeFocusedArticle()` 内部包含一段写死的 Anthropic 技术长文模板（含固定字面量、三类场景、47.49%→59.00% 基准），根本未引用 LLM 选题的 7 个字段（`topicTitle`, `heading*` 等），导致无论选中什么推文，产出的都是 Anthropic 文章。
2. **选题无历史记忆**：Stage 2 审稿人仅看当次抓取的推文候选，未记录历史已写推文与文章标题，导致相同推文被反复重复选中。
3. **违反 No-Fallback 原则**：缺失字段使用 `'Anthropic 官方技术长文'` 等字面量兜底，主标题 prompt 甚至误导 LLM 挂帅 Anthropic。

## 2. 修复措施与架构改造
1. **彻底拔除硬编码模板，改为基于真实素材的动态生成**：
   - 移除所有 Anthropic 预制正文字面量。
   - `buildArticleMaterial()` 汇集当次选定推文原文、外链长文爬取内容及 Grok 补充信息，作为 LLM 唯一的事实来源。
   - LLM 提示词强制要求严禁出现素材外的机构、论文和百分比数字。
   - 增加 `validateArticleBody()` 强校验（一级标题、4个动态小标题、插图占位符、字数、素材一致性检查），校验不通过重试，重试失败直接 Fail-Fast，绝不兜底。
2. **基于 Summary 物理去重的历史机制 (`history.ts`)**：
   - 从输出目录读取最近 8 期 `xdev-summary-*.json`。
   - 实现 `splitByHistory()`，提取 Tweet Status ID 进行程序化物理剔除。
   - 将已写过清单（标题、议题、结论）注入 Stage 2 审稿 Prompt，要求新一期必须差异化。
   - 若候选推文全部写过，立即报错中断，严禁复用旧题材。
3. **补齐单测覆盖**：
   - 验证 ID 提取、历史过滤、破损 summary 容错。
